# CI-Spatial goal-readiness audit, 2026-11-13

Scope: the whole-house and whole-office tagged-glTF goal across phone web (8th Wall in Safari, WebXR in Chrome), the iOS and Android Capacitor shells, the desktop editor and catalogue, headset WebXR, computer-vision tagging, the tagged glTF output, multi-room alignment, and device-test readiness.

Basis: the working tree on 2026-11-13, which includes uncommitted work. Paths and line numbers refer to that tree.

Method: seven read-only area audits, each with a structured report, then one lead merge that dedupes the gaps and checks the load-bearing claims against the working tree. Nothing ran on a phone, a headset, Xcode or the Android SDK. Where a claim depends on a device, it is listed under user actions, not verified here.

## Summary

Lead merge of the seven area reports for the goal: phone scanning on iOS and Android, plain web, headset scanning and editing, a desktop editor, and one tagged glTF of a whole house or office. Nothing ran on a phone, headset, Xcode or the Android SDK; this machine has JDK 21 but no Gradle, adb, Xcode or Android SDK. The lead read the publish-readiness audit and re-checked the load-bearing claims listed in the risks against the working tree; every cited repo path and function name was confirmed to exist. The 81 gap entries merge into 52 buildable items in six waves (each item names its source gaps) and 26 user actions. Verdicts: none works end to end on a device; 10 requirements are partial and headset editing is missing. The largest gaps: (1) Thing matching and positions compare each session's own origin, so one localToWorld fix resolves five reports; (2) there is no whole-Place tagged glTF, because export-world is a placeholder job; (3) tag identity is positional and is lost on re-scan; (4) on-phone feedback is wrong (pins are sized to the window, the verified alignment message is overwritten, and poses latch while LIMITED). Buildable and testable here with Node, Deno and iwer emulation: all six waves, except the parts that need a device. Not buildable here: any on-device verification (iPhone 8th Wall, Android WebXR, a headset), the ARKit and ARCore code, any iOS or Android build, placement and cross-room accuracy measurements, and the native file save. Audit correction: F47 is marked fixed, but auto-capture and pose history still gate on the latched isTracking().

## Risks and corrections

- Frame fix rewrites Things (W1-1): correspondence overwrites a world's things (server/main.ts around 3569-3570). Copy each world JSON before any rerun, and expect different Thing counts and positions afterwards.
- Uncalibrated scans lose their accidental matches after W1-1, so expect more duplicates among them until they are calibrated (user decision 3). Do not widen the 0.75 m match radius to hide this.
- The compass fix (W4-13) must wait for the handedness question (audit F53) to be settled on a device. A sign error would mirror east and west for every uncalibrated scan.
- GLB contract changes (W1-4 to W1-6) affect readers of legacy files: 13 of 16 readable raw GLBs carry the legacy dimensions object, and 8 carry thumbnails. Readers must accept both shapes. Thumbnails stripped from a file cannot be recovered from the GLB; the IndexedDB copy remains.
- Node names and objectIds must not change (gltf.ts around 332-334). The viewer's LOD ids (viewer.ts around 1636) and the server's targetId (server/main.ts around 3644) must stay in step; change them only through one shared helper.
- The keyframe-session change (W4-4) alters the server's join, which is keyed by glbFilename (scan_index.ts). The join is unverified, so test against a copy of sessions/ and scans/ before any server change goes live.
- New routes (W2-1 export, W2-5 deletes and renames, W2-6 Area edits, W4-6 precondition) must sit behind denyUnlessWorldRole with route-guard tests. The audit found that Hono's literal path guard left world reads anonymous (F3, F19, F40), and no route-guard tests exist (audit section 10).
- The Place PUT precondition (W4-6) changes an API contract: older clients will see 409s, so ship client and server together.
- Browser checks are weak: the newest recorded Playwright baseline (2026-11-02) had 30 failures. Record a baseline on test-box with isolated ports before wave 3, and never run specs against the phone-test services.
- Every UI change must keep pinch zoom and 16 px text fields on touch screens (npm run test:viewport; CLAUDE.md).

### Multi-room alignment and device-test readiness (8th Wall Safari, WebXR Chrome, Capacitor shell, headset, desktop editor)

What works:

- Within one AR session, every room shares the SLAM frame with no calibration needed, and the viewer applies each scan's localToWorld to its root (src/viewer/viewer.ts:1560, 2391), so GLB geometry lands where the export placed it.
- The two-point frame math is internally consistent: landmark to origin, heading marker onto +Z at the recorded separation (src/world/geo.ts:258-290), and the sign is load-bearing with an in-file test reference.
- A verified return visit keeps the stored Place frame, and only a changed frame is written (src/ar/project-calibration.ts:1068, 1129-1133; src/main.ts:1874-1876).
- Places are isolated: each Place has its own world, so scans from different Places cannot mix in one world (server/world/world_membership.ts:17-24; server/main.ts:2814-2846).
- Manual correction exists and persists: a gizmo move becomes an EditPatch that sets localToWorld (server/main.ts:3204-3209, 5429), the viewer replays it (src/viewer/viewer.ts:1676-1690), and applyMatrix overwrites rather than multiplies (src/viewer/viewer.ts:4350-4356), so the replay is idempotent.
- A calibrated scan takes precedence over GPS: projectTransform wins over the GPS fallback (server/main.ts:2542-2546), so a walk in a Place with a stored frame aligns without any GPS fix.
- Not aligning is not an error: the scan still saves, the server places it by GPS or on a 3 m grid, and the phone shows a 'No project alignment' status (src/main.ts:1905-1907). Q1-2 explains how wrong that placement is.
- Device entry points exist: /smoke.html (public/smoke.html), /webxr.html (forwards its query string, webxr.html:124-135), the scanner ids in the device docs (index.html: #start-ar-btn, #capture-btn, #auto-capture-btn, #stream-btn, #rtc-stream-btn, #finish-scan-btn, #pose-readout), and the ?debug=pose readout.
