Companion Scan, mapped

A browser-based AR room scanner: point your phone at a room over Tailscale, and a Deno server turns the walk-through into a labelled 3D world — point clouds, Gaussian splats, and a shared multi-scan editor. This atlas indexes every feature, the data it moves, the variables that steer it, and how its pieces actually talk to each other, built by reading the source directly rather than the docs.

Living document — docs/factory/atlas.html, versioned by git. The base research is the 2026-08-15 source read; Development waves and the before/after markup threaded through it track what each planned wave changes. Every new wave updates this file as part of its planning — see docs/FACTORY.md § “The atlas”.

Development waves

Everything else in this atlas describes the codebase as read on 2026-08-15. Since then, eight planning waves in docs/factory/ have turned the duplication this atlas found into tracked, ticketed work — and then kept going past it. Two are complete; 02-typed-event-payloads is unblocked; 03-readiness-hardening and 04-capture-path-truthfulness are underway; 05, 06, 07 and 08 are planned. The later waves no longer come from this atlas's duplication audit at all: 03 came from a readiness review, 04 and 06 from real on-device sessions that caught the system reporting success it had not earned, and 07–08 from a scan-identity investigation on 2026-08-19. This section maps that work; the diff blocks threaded through the rest of the atlas mark exactly where each wave lands. Ticket content itself lives only in docs/factory/ — nothing here duplicates or replaces it.

The wave this atlas's own review kicked off: reconcile the license docs, fix a live hostname bug, then work through every duplication the review found — two ScanManifest types, a copy-pasted PLY parser, five copies of the manifest envelope, raw event-type strings, undocumented env vars, a magic-numbered port, and the Companion-Scan/CI-Spatial naming split.

01-merge-jobs

5 / 5 done
docs/factory/01-merge-jobs/
design → runner hardening → port optimize-scan → shims → retirement — landed 2026-08-16

Merged the two background-job systems this atlas flagged — jobs.ts's JobQueue and the WorldJob system — into one, canonical survivor WorldJob. Strictly serial: the runner gained crash recovery and single-flight execution before optimize-scan moved onto it, so the merge was a strict upgrade, not a regression.

Impact: jobs.ts's JobQueue class is retired (the file survives, trimmed to the legacy type definitions the back-compat shim still needs). Every background job — GLB optimize, LingBot-Map, splat train/detect/finish, memory-push — runs through one queue (world_job_pump.ts), one status vocabulary, one event stream, with crash recovery, dedupe, and bounded history for job types that never had them. See the wave README's "Landed" section for what was found along the way — including a pre-existing, unrelated viewer.ts race flagged as a follow-up.

02-typed-event-payloads

0 / 3 done
docs/factory/02-typed-event-payloads/
was sequenced after 01-merge-jobs — that wave landed 2026-08-16, so this one is now unblocked

Gives every /events WebSocket message a real, discriminated-union TypeScript type. Deliberately sequenced after 01-merge-jobs — typing job-event payloads before the merge means typing two independently-drifting shapes; after it, both the legacy 'job-update' shim and 'world-job-update' derive from one settled model.

Impact once shipped: a mistyped event field becomes a compile error, not a runtime surprise — its own design ticket cites a real near-miss from this atlas's audit, where a duplicated string literal for an event type almost got a live branch misdiagnosed as dead code.

03-readiness-hardening

5 / 6 done
docs/factory/03-readiness-hardening/
toolchain first (0001–0003), then the three product defects (0004–0006) in parallel

Closes the six items left open by a full readiness review of the scan → pin → export → editor path. Unlike the waves above, this one did not come from this atlas's duplication audit — it came from running every documented check tier and finding that two of them ran no tests at all. npx playwright install aborts on this host's OS, so npm test and test:mobile failed every test at browser launch; the editor transform defect (0004) lived behind that. The toolchain tickets are sequenced first for exactly that reason.

Impact once shipped: an object moved in the World Editor comes back where you put it — the one clause of the scan → pin → export → editor bar that does not hold today. Alongside it, GET /scans stops being quadratic (a ~2,900-file library took 120s), the map stops depending on an external CDN, and the two WebKit tiers become runnable on an unsupported host instead of silently reporting nothing.

04-capture-path-truthfulness

2 / 5 done
docs/factory/04-capture-path-truthfulness/
0001–0002 ✓ (PR #112) — 0003, 0004, 0005 open

Five defects on the capture path, all found in one Lume Pad 2 session on 2026-08-18. They are one wave because they are one failure mode: each reports success it has not earned, and none produces an error a user could act on. A model that copied its own prompt example into 219 scans; a WebXR provider feeding one point per frame while the HUD blamed the user for sweeping too fast; a capture destroyed when inference fails; a WebGPU toggle that has never worked; and six byte-identical JPEGs across 47 minutes.

Impact: the capture path stops lying. 0001 and 0002 landed — the detection model can now actually do structured detection, and the WebXR provider samples the 6×6 probe grid the scanner always asked it for. The three open tickets stop a failed inference from destroying the only unrepeatable artifact, gate a claim the product cannot honour, and stop handing every capture the same frozen frame.

05-on-device-inference

0 / 4 done
docs/factory/05-on-device-inference/
extract driver → provision weights → WebGPU runtime → ungate the toggle

Makes the WebGPU inference toggle real, rather than deleting it. The product offers "On-device — no data leaves your phone" and has never been able to honour it: no released Transformers.js registers the pipeline task the worker asks for. Porting was chosen over removal deliberately — the claim is strategic to a product whose tagline is "Private spatial memory for places you own," and most of the work already exists, since inference.ts already drives LFM2.5-VL by hand.

Impact once shipped: the toggle wave 04 gated becomes a real capability — the same model running in the browser on onnxruntime-web, with a stated fallback policy when the device cannot run it.

06-detection-ground-truth

0 / 3 done
docs/factory/06-detection-ground-truth/
real corpus → retarget eval/bench → regression gate

Nothing in this repo can tell whether object detection works. Measured 2026-08-18: a driver that correctly identified a mug, two keyboards, a monitor, a tripod and handwritten paper on a real photograph scores 0.0% precision, 0.0% recall and 0.000 mean IoU on npm run eval:cv, across all 16 corpus images — because the corpus is solid palette-coloured rectangles built for the deterministic mock detector. It is a good pipeline regression test and cannot be a test of whether a vision model sees things. README.md nonetheless tells you to pick your model with it.

Impact once shipped: model choice stops being ranked against a fixture that punishes working models, and a detection regression becomes something CI can actually catch.

07-scan-identity

2 / 4 done
docs/factory/07-scan-identity/
unique scanId + migration → one session identity → node provenance → pipeline guard

Four tickets on one question the system cannot answer: which scan is this? A scan's id is derived from the capture session, a capture session is one browser tab, and a tab produces many uploads — so every autosave in a walkthrough collides onto one id. Observed 2026-08-19: worlds/default.json holds four distinct GLBs under one scanId, and the viewer discards three of them at load while the HUD reports "1 scan loaded". Edit-patch replay, memory-push idempotency and job GC all resolve to whichever scan they find first.

Impact once shipped: every uploaded scan exists, loads and toggles independently; keyframe jobs fail at preflight with a reason instead of inside the runner; and every node in an exported GLB records which session and capture produced it — which is what makes a later merged per-place GLB reversible.

08-places-and-things

0 / 9 done
docs/factory/08-places-and-things/
blocked on 07 — place model → registry → picker → management → world-as-view; observations → correspondence → tags; scrubber

Makes the tagline true. "Private spatial memory for places you own" — yet there is no concept of a place, no thing that persists between visits, and no way to look at a moment in time. Two of the three were designed and never wired: Project/Floor/Room/ScanEntry are fully typed with an IndexedDB index and a server CRUD mirror, but projectStore is constructed at src/main.ts:163 and never referenced again. Meanwhile synthesizeWorld ignores its own slug and every world absorbs every scan on disk. The ownership rule that resolves it: Project owns scan membership; World derives it.

Impact once shipped: a scan records the place it was captured at, a world is a view over one place's scans rather than a global bucket, every observation survives with its own session and timestamp, a heuristic job says which things were added, removed or moved between visits, a timeline scrubs the composite, and a tag applied once follows its thing across future visits.

The first three waves don't change what the system does. Every ticket across foundation-updates, 01-merge-jobs and 02-typed-event-payloads preserves current behavior — wire formats, on-disk formats, storage keys, and defaults stay byte-identical. That is the "harden" half of "unify and harden the repo," not a feature wave. (Two behavior changes did land alongside 01-merge-jobs, both deliberate and both outside its tickets — see below.)

03-readiness-hardening is the exception, deliberately. It exists to fix defects, so three of its six tickets change observable behaviour: a transform patch starts applying to the node it was taken from (0004), GET /scans stops re-sweeping the sessions directory per scan (0005), and Leaflet stops being fetched from unpkg at runtime (0006). Wire formats and on-disk formats still stay byte-identical.

Wraps the 8th Wall engine for 6-DoF pose, per-frame SLAM point harvesting, and hit-testing (0.08–50m sanity filter). A 5s fallback force-unlocks capture if SLAM never reports a pose.

Native immersive-ar for Android/Quest. WebXR exposes no SLAM feature points, so it substitutes a rolling buffer of hit-test rays and opens a companion camera stream for pixel capture.

splat_train.ts · splat_detect.ts · splat_finish.ts · lingbot_map.ts

Spatial Reconstruction

A second, higher-fidelity pipeline that turns a session into a dense point cloud and a trained 3D Gaussian splat — each stage shells out to an external native tool and degrades to a "skipped" manifest instead of crashing when that tool is unavailable.

LingBot-Map reconstruction

Spawns a Python worker running the LingBot-Map transformer to merge a session's keyframes into a dense point cloud + per-frame poses. Missing torch/checkpoint → graceful skip, not a crash.

lingbot_map.tslingbot_map_worker.py

Gaussian-splat training

Builds a Nerfstudio dataset from keyframes and trains a 3DGS splat via the external Brush CLI (Rust/wgpu), falling back to LingBot-Map's estimated poses for pose-less video/photo ingests.

Splat-based object detection

Renders the trained splat and runs an external open-vocabulary OWLv2 detector (splat_analyzer) to produce 3D bounding boxes, with tunable score/vote thresholds.

External-worker detection

Both splat workers probe for their binary before running and fall back to a skipped manifest with a remediation hint when it's absent — which is what lets the whole pipeline run end-to-end in CI without Brush or a python venv installed.

License contradiction — fixed. README.md's License section said MIT. LICENSE.md is actually a restrictive "Commercial Standard License" (CI-Commercial-1.0, © 2019–2026 LifeScope INC).
README.md § License: "MIT"→correctly names the Commercial Standard License, links to LICENSE.md, flags which-license-is-intended as an open owner question rather than resolving it✅ done foundation-updates/0001, merged in #68
Confirmed live — fixed. ALLOWED_ORIGIN_PREFIX defaulted to a hardcoded fallback host (liambook.capybara-ulmer.ts.net) rather than the machine's own auto-detected Tailscale hostname. Harmless for CORS (the allowlist independently trusts any *.ts.net origin) but broke share-link generation.

World writes had no read-modify-write lock — fixed. saveWorld() wrote atomically (tmp file + rename), but nothing guarded the surrounding loadWorld() → mutate → saveWorld() cycle, and main.ts contained no mutex of any kind. Concurrent cycles clobbered each other: a writer holding a pre-completion snapshot reverted a finished job to processing, where it stayed until the next boot's recovery pass.

Observed, not theorized — a test:box run on 2026-08-16 left 4 jobs stranded at progress: 0.35 (the exact value _dispatchWorldJob writes when it marks a job processing), updatedAt spread 14s apart, while other jobs kept completing for ~3 minutes after. The pump is strictly serial, so concurrent execution can't explain it.

01-merge-jobs made this materially worse: optimize-scan used to persist to its own scans/jobs.json with exactly one writer (the retired JobQueue). It now writes the same worlds/default.json that every upload, job transition, and editor action writes — which is what turned a latent race into a reproducible one.

any code path could loadWorld(), mutate, and saveWorld() whenever it liked→world_lock.ts's per-slug promise chain (the shape enqueueScanLoad() already uses per scanId) fronts three locked entry points — loadWorld, updateWorld, mutateWorldFiles — over the deliberately-named readWorldUnlocked/writeWorldUnlocked primitives; workers and broadcasts stay outside the critical section✅ done ADR 0004 — the two job specs that used to flake under load now pass first try; world_lock.test.ts pins both halves
"Pre-existing and environmental" was wrong — fixed. Nine splat_detect/splat_train tests failed on Windows and were recorded as pre-existing, environmental, and unrelated in four separate 01-merge-jobs tickets. The evidence offered each time (an empty git diff on the test files) only ever showed the wave hadn't caused them — never that they were environmental.
isRunnable() masked mode & 0o111, with a fallback for mode === null on "unsupported platforms"→Windows never reports null — it synthesizes 0o100666, exec bits always clear, so the fallback never fired and every binary (including the running deno.exe) read as non-runnable✅ done PR #80 — Windows went 96/9 → 111 passed, 0 failed
Two job systems, same repo — unified. jobs.ts's JobQueue (GLB optimize) and the WorldJob system (lingbot-map/splat/*) used to be entirely separate — different manifest schemas, different queues, and they never called into each other.
don't assume a change to one affects the other→WorldJob is the one queue now, per ADR 0001's "no third system" rule and ADR 0003's merge design✅ done docs/factory/01-merge-jobs, merged 2026-08-16 — see Development waves for what landed and what it caught along the way
